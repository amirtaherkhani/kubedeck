# v1.0.0 — restore the usable local platform

**Priority:** P0, immediate. **Scope:** the current Mac and its running Docker Desktop built-in Kubernetes cluster, for local development. **Release outcome:** required tools are usable from this system by documented DNS names and connection endpoints. Do not wait for the later module manager or full UI operations suite.

## Local DNS and changing Mac IP

The Host Agent discovers the active macOS IPv4 address and reconciles the Technitium wildcard answer to the local ingress address. It runs on the current Mac and retries after network changes and launchd restarts. Keep the scoped resolver pointed at the local Technitium listener. No host IP, interface, or local file path belongs in shared chart values.

## V1 release gate

- Required service matrix has no untriaged `unknown` or `failed` critical row.
- DNS resolution, TLS, authentication, application response, and persistence pass from the Mac and its local dependent-project workflows, including after an IP change and Docker Desktop restart.
- Infisical development secrets are usable after verified restore, with no values in public evidence. Stateful data survives intended restart or has an accepted reseed policy.
- Caretta and Radar provide verified local service-traffic visibility when the Docker Desktop eBPF compatibility gate passes; each required external project passes its own development smoke flow.
- Rollback assets stay available through the accepted window. Cleanup of old Rancher/DNS resources is a separately recorded action, not a hidden release prerequisite.

**Explicitly out of scope:** a separate KubeDeck-owned kind cluster, generalized module install/uninstall UI, complete Docker build history UI, and Tekton/Buildkite adoption.
