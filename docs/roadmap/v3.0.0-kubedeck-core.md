# v3.0.0 — KubeDeck core

**Status:** Deferred. This version restores the project's own dashboard and Kubernetes Agent after the platform foundation and project workflows are stable. The source code and Helm charts remain maintained in the project; this roadmap defers their runtime deployment, not the product.

## Delivery sequence

```text
V3-01 data and deployment contract
  -> V3-02 supported dashboard/Agent images and charts
  -> V3-03 authenticated dashboard and live Agent workflows
  -> V3-04 safe management operations and release acceptance
```

| ID | Priority | Scope | Acceptance |
| --- | --- | --- | --- |
| V3-01 | P0 | Revalidate the KubeDeck dashboard and Kubernetes Agent architecture against the current Docker Desktop cluster; define the supported image registry, version pairing, resources, database/data ownership, backup/restore, secrets, DNS, TLS, and rollback policy. Keep the dashboard and Agent as a paired product deployment. | An approved deployment contract identifies retained state, upgrade/rollback behavior, least-privilege access, and exact supported image/chart versions. |
| V3-02 | P0 | Build and publish matching dashboard and Agent images from the project Dockerfiles; retain and validate both Helm charts and their configuration. | Reproducible builds resolve to immutable image digests; chart lint/template and upgrade/rollback checks pass without losing retained data. |
| V3-03 | P0 | Deploy the pair and validate authenticated login, API proxy, live snapshot/SSE events, discovery/catalog, and the supported local DNS/HTTPS route. | A real Docker Desktop target demonstrates the complete user workflow with no illustrative fallback or unauthenticated management access. |
| V3-04 | P0 | Validate read-only defaults, each explicitly enabled management operation, recovery after Docker Desktop restart, and release documentation. | Security, persistence, recovery, and rollback evidence is recorded; dashboard and Agent versions are compatible and accepted as one release. |

## Boundaries

- V3 is scoped to the current Mac and its Docker Desktop Kubernetes cluster.
- The dashboard and Kubernetes Agent source, Dockerfiles, chart templates, and values stay in this repository while runtime deployment is deferred.
- Existing PVC data and Infisical-managed credentials are retained during the V1 runtime removal. Their backup/restore policy must be settled before V3 changes or consumes them.
- Do not restore either runtime release independently; validate and deploy the supported dashboard/Agent pair together.
- V1 platform readiness and approved client workflows are prerequisites, not substitutes for KubeDeck product acceptance.
