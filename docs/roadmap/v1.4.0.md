# v1.4.0 — portable installation and enforceable controls

**Outcome:** another developer can set up KubeDeck on a different Mac without editing committed IPs, ports, paths or identities; the UI can limit capabilities while enforcement remains server-side. **Depends on:** v1.0.0 bootstrap and v1.1.0 host agent. This release does not require remote multi-host management.

| ID | Priority | Work | Observable acceptance |
| --- | --- | --- | --- |
| V14-01 | P1 | Replace remaining Rancher context, fixed IP, fixed interface, local path and machine identity assumptions with installation profile, discovery and validated local overrides. Provide Docker Desktop prerequisite/version/capacity preflight and reversible setup. | Fresh Mac setup reaches the same core service/DNS acceptance path using only documented local configuration and its own LAN IP. |
| V14-02 | P1 | Package/sign/install Host Agent with macOS launch lifecycle and explicit admin privilege setup for network and Docker operations; keep Go core and OS adapter boundaries for later Linux/Windows ports. | Host agent starts after reboot, reports missing permissions accurately and recovers from network/Docker restarts without manual commands. |
| V14-03 | P1 | Add UI roles/capability policy, approval/confirmation for destructive actions, credential rotation and scoped API authorization **enforced by both agents**. Full underlying capability remains available to an authorized local administrator. | Attempts from lower roles fail at the API/agent even with a crafted request; audit records actor, action, target and result without secret payload. |
| V14-04 | P2 | Verify install/upgrade/backup/restore/uninstall documentation and compatibility across supported Mac hardware/network profiles; publish troubleshooting for router DNS bootstrap, port conflicts and Docker Desktop limitations. | A second Mac completes an independent reproducible install and recovery drill; known unsupported router/OS combinations are documented. |

**Release gate:** second-Mac validation, not a local reinstall on the original machine. No cloud or internet-facing cluster API is required.
