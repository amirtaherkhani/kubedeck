# v1.1.0 — complete local agent control

**Outcome:** a Go Kubernetes Agent and a separate Go Host Agent expose the local capabilities needed to operate the Docker Desktop platform. **Depends on:** v1.0.0 access and a stable service inventory. Plan the exact capability contract and host permission model before implementation.

| ID | Priority | Work | Observable acceptance |
| --- | --- | --- | --- |
| V11-01 | P1 | Split contracts by target: Kubernetes API/Helm in cluster agent; Docker Desktop/Engine/BuildKit and macOS network in host agent; Technitium through a DNS adapter. Define versioned capability discovery, target identity, request IDs, errors, idempotency and audit events. | UI never routes a Docker or host operation to a pod-only agent; unsupported operations report a precise capability error. |
| V11-02 | P1 | Extend the existing Go Kubernetes management API (v0.2.0 already covers bounded CRUD, logs/events and rollout/scale). Add the missing approved operations: Helm install/upgrade/rollback/uninstall, workload exec/attach and port-forward where needed, node/namespace operations, pod create/replace and deployment controls. Use Kubernetes and Helm APIs, preconditions and bounded streams. | Each exposed operation works on the Docker Desktop target with authenticated request, target check, audit trail, timeout/cancel, and conflict-safe retry; no action relies on shelling out from the UI. |
| V11-03 | P1 | Build Go Host Agent with macOS adapter for network service/IP change observation, DNS/route/port diagnosis, supported Docker Desktop start/stop/restart/settings APIs, Docker Engine containers/images/volumes and BuildKit/buildx. Keep OS-neutral contracts and separate adapters for future systems. | Agent recovers after Mac login/restart and network change; current IP and Docker state are accurate; supported lifecycle actions work and unsupported settings are explicitly reported, not silently edited. |
| V11-04 | P1 | Connect UI/API and agents: REST for finite commands and current queries; SSE with replay/heartbeat for status, events, logs and build progress; WebSocket only for bidirectional terminal/exec. Use Socket.IO only if its additional protocol features are needed. Define auth, backpressure, reconnect and cancellation. | Browser reconnects without duplicate operations; long streams end on cancel; command results and audit IDs match observed target state. |

**Authority boundary:** The agents should be capable of the full set of **supported** local Docker, Kubernetes and host operations. Platform limitations still apply: a pod cannot administer macOS without a host process, Docker Desktop settings must use supported interfaces, and macOS privileged network changes require the appropriate user/admin grant. Broad agent capability must not mean unauthenticated remote execution; the UI restriction planned for v1.4.0 must be enforced by the API/agents, not only by hiding buttons.

**Release gate:** all advertised capabilities are exercised against the intended Docker Desktop context; denied/unsupported operations have stable errors; commands are authenticated and audited; host agent failure does not break Kubernetes discovery or DNS answers already served by Technitium.
