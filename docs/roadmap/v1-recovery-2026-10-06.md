## Recovery order

1. Obtain router model for LAN client bootstrap. The wildcard **answer** follows the Mac IP, but clients still need a stable way to find the DNS **server**.
2. Confirm isolated Infisical database backup/key custody. Current export-record equality is useful migration evidence but does not replace the full protected backup gate.
3. Back up and restore the new S3 PVC together with its SSE-S3 key, then exercise an actual consumer project. The configured MinIO image digest remains unavailable and its old PVC is retained. Do not change the PostgreSQL image family or major version on its populated PVC without backup and a migration plan. Select the remaining observability and test tools based on active projects.
4. Verify the deployed KubeDeck dashboard and Kubernetes Agent through selected management reads, restarts and actual client development workflows before release.

The Docker CLI's image store is distinct from the built-in `kind` node's runtime: a temporary pod using a Docker-pulled image with `imagePullPolicy: Never` returned `ErrImageNeverPull`. It was deleted. The PVC-backed local registry is reachable on the Node's `localhost:5001`; Mac-side `crane` pushes through a scoped `kubectl port-forward`. An Agent smoke Pod pulled its image in 181 ms, and both image digests survived a registry Pod restart. This registry design is restricted to one Ready Docker Desktop node.

The repeatable entry points are `lab/scripts/docker-desktop-core.sh validate|apply`, `lab/scripts/docker-desktop-object-storage.sh validate|apply`, `lab/scripts/docker-desktop-metrics.sh validate|apply`, and `lab/scripts/docker-desktop-kubedeck.sh validate|images|apply`. They check the `docker-desktop` context and apply the Docker Desktop profiles. The core and KubeDeck scripts resolve this Mac's `home-lab` Infisical project slug; `INFISICAL_PROJECT_SLUG` can be supplied for a separate installation. The object-storage chart depends on the Infisical-managed `platform-storage/minio` Secret for its S3 credentials, but uses an independent PVC and release. KubeDeck image publication requires `crane` and uses a single-node local registry; no public registry push is needed. Existing PVCs are retained when optional modules are disabled.

## Rollback

The old `dnsmasq` launch daemon plist and configuration remain on disk during the DNS cutover. If Technitium cannot answer on 53, bootstrap `system/homebrew.mxcl.dnsmasq` again with macOS administrator authentication. Keep Rancher volumes, old app data, Infisical backup, and original decryption key untouched until their separate migration gates pass.
