# v0.10.0

## Highlights

KubeDeck is renamed KuchDesk across the repository, agents, chart, macOS integration, and GitHub location. The lab deployment now renders DNS and TLS references from one site profile. A new domain can be prepared with its own certificate before the Ingress routes change. The existing Docker Desktop Kubernetes metrics are joined by macOS host metrics and active Technitium DNS checks in Grafana.

## Added

- An opt-in Infisical-to-Helm probe verifies a dedicated secret path through
  the Operator, Kubernetes Secret, and a Helm workload. The Operator's scoped
  namespace list now includes `development-tools`; no secret value enters
  Helm values or history.
- A disabled-by-default host HTTPS bridge exposes typed Infisical project,
  environment, folder, secret, role and identity-membership commands plus
  Doctor checks. An opt-in Kubernetes-agent proxy and MCP management tool can
  use the host service without placing Infisical bootstrap credentials in a
  Pod or Helm release. Responses omit secret values. No listener, access
  grant, MCP registration or cluster rollout has been activated.
- The Kubernetes agent can return a metadata-only Job status, run one Job from a confirmed CronJob template, and delete a confirmed Job with Kubernetes UID/resourceVersion preconditions. Writes support dry run; no live operation or rollout has been performed.
- The Kubernetes agent can expose a separately enabled WebSocket port-forward to one running Pod TCP port, with bearer authentication and bounded tunnel lifetime and traffic. It is off by default and has no live rollout yet.
- The Kubernetes agent has an opt-in, noninteractive Pod exec API with exact Pod identity confirmation and bounded command output. It is disabled by default and was source-tested without a live command or rollout.
- The Infisical CLI can check whether its machine identity lists a project and whether project-detail access is allowed, forbidden, or missing. It reads metadata only and does not change grants.
- A local site-profile configuration command offers a field diff, dry-run, revision-confirmed apply, and rollback. It changes only JSON configuration; DNS, certificates, and Helm changes remain explicit operations.
- Deployment apply now checks host and cluster readiness before any build or Helm action. Profiles must set `preflightDomain` and `preflightRegistryUrl`; unavailable or warning checks stop the workflow with an actionable finding.
- A Doctor CLI and MCP tool reports deterministic, redacted host and cluster findings. An MCP prompt and JSON schema let the existing AI harness plan and verify only supported typed actions; there is no separate AI provider or key.
- A local stdio Infisical MCP binary exposes typed capability discovery and name-only secret listing. Its Universal Auth client reads the project-local `.env` by default or an explicitly selected macOS Keychain item, then reissues short-lived access tokens. No identity or live MCP service is provisioned.
- A noninteractive Infisical CLI shares the MCP command service; bounded in-memory MCP operations expose start, status, and cancellation for name-only reads.
- The management-enabled Kubernetes agent can run bounded scale/restart jobs asynchronously and report their API acceptance status; rollout health still requires a separate check.
- A host-side deployment CLI validates a source revision, runs Go tests, builds and pushes an image, resolves its registry digest, stages that digest in KIND containerd and registers it with CRI, then renders and applies a digest-pinned Helm release and checks rollout status. The host MCP process also offers an opt-in, bounded plan/start/status/cancel interface for the same profile workflow.
- An Infisical integration plan defines required MCP access, one host bootstrap credential with automatic access-token reissue, Helm/Kubernetes Secret delivery, and capability gates. No new integration service is deployed by this documentation.
- `lab/site.json` and the Go command in `lab/cmd/render-site` generate cert-manager Certificates, Traefik's default TLSStore, and Grafana/Infisical Helm overlays. An existing ClusterIssuer can be selected for another environment.
- A Host and DNS dashboard shows the existing macOS node_exporter metrics, Technitium's site-domain and public-recursion DNS probes, and Docker Desktop's host DNS path. The DNS probe name follows the rendered site profile.

## Changed

- Host-agent builds now require Go 1.25 for the official MCP Go SDK.
- Optional service alias writes target a marked block in Docker Desktop KIND's existing CoreDNS Corefile.
- A fresh Infisical PostgreSQL installation uses the cluster's default StorageClass. Existing PVCs and StatefulSets are unchanged.
- The macOS DNS reconciler accepts a configurable record TTL, run timeout, and launchd polling interval, and the installer pins the selected `kubectl` executable path.
- Use KuchDesk names for Go modules, binaries, Helm chart/resources, agent settings, API identities, documentation, and the managed macOS job. The chart version is 0.12.0 and app version is 0.9.0.
- Domain names and TLS Secret names are no longer embedded in deployable Helm base values or static manifests.

## Fixed

- A macOS-local port-forwarded registry can receive locally built images through a host-side `crane` push. An optional KIND step pre-pulls the resolved digest through each node's CRI before the Helm upgrade. Host push, node pull, kubelet Pod creation, a manual digest-pinned Helm rollout and the CLI apply path were verified; the first CLI rollout needed a corrective CRI pull after `ctr` alone left `ErrImageNeverPull`. Fresh-blob kubelet download, rollback failure and MCP apply remain unverified.
- Bound parallel authorization checks for the management capability catalog; the initial live sequential catalog took about 40 seconds for 218 resources.
- CoreDNS alias management now works with KIND's actual Corefile layout, with optimistic concurrency, dry runs, and refusal of unmanaged rewrites.
- The Kubernetes agent can use a local kubeconfig with an explicit context and multi-file `KUBECONFIG` when run outside a Pod. Ingress resource backends no longer crash snapshots.
- The host DNS reconciler refuses to publish an arbitrary private IPv4 address when its selected interface has more than one.
- The generated certificate set covers the namespace of Traefik's fallback TLSStore.
- The macOS DNS reconciler is reinstalled with its explicit zone, cluster context, and physical LAN interface, so a VPN default route no longer prevents wildcard DNS updates on this host.

## Breaking Changes

- Replace the old CoreDNS custom ConfigMap and override-key settings with `KUCHDESK_COREDNS_CONFIGMAP` and `KUCHDESK_COREDNS_COREFILE_KEY`. Remove obsolete Helm `dnsManagement.overrideKey` and `createConfigMap` settings.
- Replace `KUBEDECK_*` with `KUCHDESK_*`, `kubedeck.io/v1alpha1` with `kuchdesk.io/v1alpha1`, and `X-KubeDeck-Confirm` with `X-KuchDesk-Confirm` in integrations. The renamed Helm chart and agent authentication Secret require explicit migration.

## Migration

- Back up `kube-system/coredns` before enabling alias writes, preview with `dryRun: true`, and verify CoreDNS health. Do not reapply the PostgreSQL manifest to an existing StatefulSet: the old volume claim template is immutable and its retained PVC remains in use.
- Stop the previous `dev.kubedeck.host-agent` LaunchAgent and install `dev.kuchdesk.host-agent` with the same zone, context, and interface. Rebuild local agent images with the new module and chart references. Keep old PVC data until the replacement runtime has been verified.
- From `lab/`, run `go run ./cmd/render-site` and apply the generated certificate resources before upgrading the Grafana and Infisical releases with the generated overlays. Follow `lab/README.md` for issuance order and verification.
- Apply the generated DNS probe ConfigMap, then `apps/observability/host-dns-monitoring/` and `apps/observability/grafana/manifests/dashboard`. The DNS exporter automatically reloads a changed query name from the ConfigMap.
- For a new domain, update DNS and `KUCHDESK_HOST_AGENT_ZONE`; update Infisical's `SITE_URL` Secret through the existing secret workflow. Application configuration changes require a rollout. Existing PVC storage classes are unaffected.

## Configuration

- Enabling the host bridge later requires a private host `.env` bridge bearer,
  a TLS certificate, an explicit project allowlist, and a separately managed
  Kubernetes bearer Secret. The chart accepts only the bridge URL and
  Secret/CA ConfigMap references. `hostBridge.enabled` remains false by default.
- For the host-local registry route, set `pushMode=host-crane`, `hostPushRepository=127.0.0.1:5001/kuchdesk-agent`, and optionally `kindPrepull=true` in a trusted deployment profile. Install `crane` v0.20.6 on the host PATH. MCP plans require an absolute `KUCHDESK_DEPLOY_PROFILE_DIR`; MCP execution additionally requires `KUCHDESK_DEPLOY_ENABLED=true` and an exact release/namespace confirmation.
- For local Kubernetes-agent runs, set `KUCHDESK_KUBE_CONTEXT` when multiple contexts exist. The Helm deployment continues using its ServiceAccount by default.
- Set `KUCHDESK_HOST_AGENT_TTL`, `KUCHDESK_HOST_AGENT_TIMEOUT`, or `KUCHDESK_HOST_AGENT_INTERVAL` before running the macOS installer to override their 30-second defaults. Reinstall the managed job to apply changed launchd settings.
- `lab/site.json` selects the DNS domain, service labels, TLS issuer, and certificate namespaces. An alternate profile can be passed with `--profile`; `--domain` overrides only the domain.
- The Docker Desktop profile expects macOS node_exporter at `host.docker.internal:9101`. The macOS DNS reconciler is configured with `KUCHDESK_HOST_AGENT_ZONE`, `KUCHDESK_HOST_AGENT_KUBE_CONTEXT`, and, when a VPN owns the default route, `KUCHDESK_HOST_AGENT_INTERFACE`.
